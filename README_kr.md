# Disk Usage Map 1.0

[English](README.md) | **한국어**

Rust + egui/eframe 기반 Windows 디스크 공간 분석기입니다. 폴더 크기를 계층형 트리맵으로 표시하고 오래된 대용량 디렉터리를 찾습니다. 파일 삭제 기능은 없습니다.

## 언어 선택

화면 상단의 **Language / 언어**에서 **한국어** 또는 **English**를 선택하면 즉시 전환됩니다. 기본 언어는 한국어이며, 선택한 언어는 `%LOCALAPPDATA%\DiskUsageMap\language.txt`에 저장하여 다음 실행에도 적용합니다. 재시작이나 재스캔은 필요하지 않습니다.

버튼, 도움말, 날짜 표현, 상태 표시를 번역합니다. 폴더·파일 이름과 경로는 변경하지 않습니다. 운영체제에서 제공하는 오류 상세는 Windows의 언어로 표시될 수 있습니다. 기존 스캔 DB는 언어와 관계없이 그대로 사용합니다.

## 실행

Windows에서 Rust의 MSVC 도구 체인과 Visual Studio Build Tools의 **Desktop development with C++** 구성 요소가 필요합니다.

```powershell
cargo run --release
# 시작 경로 지정 (자동 스캔하지 않음)
cargo run --release -- "D:\\"
# 실제 드라이브를 읽지 않는 화면 데모
cargo run --release -- --demo
```

빌드 결과: `target/release/diskusagemap.exe`. 실행 후 드라이브를 선택하거나 폴더 경로를 입력하고 **스캔 시작**을 누릅니다. 이동식 드라이브 연결 후에는 **드라이브 새로고침**을 누르세요.

## 시작 시 저장된 지도 복원

스캔 완료 시 폴더별 크기·날짜·계층·누락 상태를 **SQLite 파일 DB에 자동 저장**합니다. 다음 실행에서는 마지막으로 저장된 지도를 복원하므로 전체 드라이브를 다시 읽을 필요가 없습니다.

- 저장 위치: `%LOCALAPPDATA%\DiskUsageMap\snapshots.sqlite3`. SQLite를 실행 파일에 포함하므로 별도 설치가 필요 없습니다. DB는 Windows 사용자별로 저장됩니다.
- 각 스캔 경로의 최신 결과를 보관합니다. 시작 경로를 명령줄로 지정하면 해당 경로의 저장 결과만 찾습니다. 경로를 지정하지 않으면 가장 최근에 저장한 결과를 엽니다.
- 경로를 입력하고 **저장 결과 열기**를 누르면 그 경로의 결과를 복원합니다. 원본 드라이브가 연결되지 않아도 저장된 지도를 볼 수 있습니다.
- 저장 결과에는 **저장 시각(로컬 시간)**을 표시합니다. 저장 이후 파일 추가·삭제·크기 변경은 자동 반영되지 않으므로 **현재 폴더 재스캔** 또는 **전체 다시 스캔**으로 갱신하세요. USN 기반 증분 갱신은 아직 구현하지 않았습니다.
- 중지·실패·진행 중인 결과와 데모는 저장하지 않습니다. 읽기 누락이 있는 완료 결과는 누락 표시와 함께 저장합니다.
- 읽기·쓰기는 백그라운드에서 수행합니다. 저장 중 정상 종료를 요청하면 저장을 마친 뒤 닫습니다. 저장 실패는 하단에 표시하고 앱을 열어 둡니다.
- SQLite 트랜잭션으로 경로별 결과를 교체하므로 저장 실패나 강제 종료 시 이전에 커밋된 결과를 유지합니다. 손상되거나 호환되지 않는 DB는 덮어쓰지 않고 오류를 표시합니다.
- DB에는 폴더 경로·집계 메타데이터와 오류 메시지가 저장되며, 개별 파일 내용이나 MFT 원시 레코드는 저장하지 않습니다. MFT의 파일별 인덱스를 다시 만드는 기능은 아니며, 바로 그릴 수 있는 폴더 지도를 복원합니다.
- 저장 데이터가 필요 없으면 앱을 종료한 뒤 위 DB 파일을 삭제할 수 있습니다. 호환 오류가 발생하면 DB를 다른 이름으로 옮긴 뒤 새 스캔을 시작하세요.

DB 복원 속도는 저장된 폴더 수와 저장장치에 따라 달라집니다. 첫 스캔은 기존과 동일하게 필요합니다.

## 탐색기에서 삭제한 항목 반영

**루트 바로 아래 항목도 안으로 들어가지 않고 새로 고칠 수 있습니다.** 예를 들어 휴지통을 비운 뒤, 드라이브 루트의 하위 폴더 목록에서 `$Recycle.Bin`을 한 번 클릭해 선택하고 **선택 항목 새로 고침**을 누르세요. 해당 폴더만 재스캔하며 현재 보고 있는 루트 지도는 그대로 유지합니다. 용량이 0이 된 폴더도 목록에서 선택할 수 있습니다.

- 하위 폴더 목록: **한 번 클릭은 선택**, **두 번 클릭 또는 열기 버튼은 폴더 진입**입니다.
- 목록 항목이나 트리맵의 폴더 블록을 **우클릭 → 선택 항목 새로 고침**으로 바로 갱신할 수도 있습니다. 트리맵도 **한 번 클릭은 선택**, **두 번 클릭은 폴더 진입**입니다. 선택한 타일은 테두리로 표시합니다.
- 선택한 폴더의 경로를 표시하고, 갱신으로 내부 번호가 바뀌어도 같은 경로의 선택을 유지합니다. 선택된 폴더가 삭제됐다면 선택을 해제합니다.

지도나 하위 폴더 목록에서 갱신할 폴더로 들어간 뒤 **현재 폴더 재스캔**을 누르세요. 예를 들어 `D:\Downloads` 아래 폴더를 탐색기에서 삭제했다면 `D:\Downloads`를 열고 이 버튼을 누르면 됩니다.

- 선택한 폴더와 그 아래 전체 계층만 다시 읽어 삭제·추가·파일 크기 변경을 반영합니다. 하위 폴더 재스캔은 폴더 열거 방식을 사용합니다.
- 현재 보고 있는 폴더 자체가 삭제됐다면, 접근 가능한 부모의 실제 목록에서 삭제를 확인한 뒤 지도에서 제거하고 남아 있는 가장 가까운 상위 폴더로 이동합니다. 여러 단계의 상위 폴더가 함께 삭제된 경우도 처리합니다.
- 상위 폴더의 용량·파일 수를 다시 합산합니다. 날짜를 정확히 다시 계산하기 위해 상위 폴더의 **직속 파일 메타데이터**도 읽습니다. 다른 하위 폴더 내부는 다시 스캔하지 않습니다.
- 재스캔 중에는 기존 지도를 유지합니다. 읽기 오류가 발생해도 다른 폴더는 계속 갱신합니다. 읽지 못한 폴더는 이전 집계를 유지하고 부분 집계로 표시하며, 정상적으로 읽은 폴더의 변경·삭제는 지도와 DB에 반영합니다. 폴더 항목을 일부만 읽었을 때는 직속 파일의 이전 집계와 확인하지 못한 기존 하위 폴더를 보존합니다. 중지·루트/드라이브 경로 확인 불가 시 기존 지도와 DB를 보존합니다. 경로가 파일이나 링크로 바뀌면 상위 폴더에서 재스캔하세요.
- 변경된 하위 결과를 원래 전체 지도에 병합해 같은 루트의 DB 결과를 자동 갱신합니다. 다음 실행에서도 삭제된 항목이 다시 나타나지 않습니다.
- 다른 폴더의 정보는 이전 시점의 결과입니다. 하단에 **부분 갱신** 범위를 표시하며 저장 시각은 전체 드라이브의 재스캔 시각을 뜻하지 않습니다. 이전 오류·제외 수와 상세는 누적 진단으로 유지합니다. 상위 폴더의 기존 누락 표시는 보수적으로 유지할 수 있습니다.
- 탐색기의 휴지통 이동이나 다른 경로로 이동한 결과까지 전체 용량에 반영하려면 **전체 다시 스캔**을 사용하세요. 파일 변경을 자동 감시하는 기능은 아닙니다.
- 원래 중지된 부분 지도를 갱신해도 미확인 영역은 남기 때문에 자동 저장하지 않습니다. 완료된 전체 결과를 확보하려면 전체 스캔을 완료하세요.

## NTFS MFT 고속 스캔

실행 파일을 **마우스 오른쪽 버튼 → 관리자 권한으로 실행**한 뒤 `C:\` 또는 `D:\`처럼 드라이브 루트를 선택하면 MFT 고속 스캔을 자동으로 시도합니다. 관리자 실행을 강제하지는 않습니다.

- 로컬 고정/이동식 NTFS 3.0/3.1 볼륨을 지원합니다. 일반 폴더 경로와 네트워크 경로는 기존 폴더 열거 방식을 사용합니다.
- 볼륨을 읽기 전용으로 열고, MFT DATA의 저장 구간(runlist)을 구한 뒤 최대 4 MiB 단위로 읽습니다. 파일마다 메타데이터를 다시 요청하지 않습니다. 드라이브 쓰기, 잠금, USN 저널 생성은 하지 않습니다.
- 권한 부족, NTFS가 아닌 파일 시스템, 지원하지 않는 구조, 손상/변경된 레코드, 스캔 중 MFT 크기·저장 구간 변경을 감지하면 잠정 결과를 버리고 기존 스캔으로 다시 시작합니다. 하단에 **MFT 고속 / 폴더 열거**와 전환 이유를 표시합니다.
- MFT 모드의 진행률은 사용하지 않는 슬롯까지 포함한 MFT 레코드 읽기 비율입니다. 부모 폴더 레코드를 읽어 경로를 연결한 항목부터 잠정 지도에 표시하므로 발견 즉시 모든 파일이 면적에 반영되지는 않습니다.
- sector fixup을 검증하고 resident/nonresident DATA의 논리적 크기, STANDARD_INFORMATION의 수정·접근 시각을 읽습니다. 확장 레코드는 기본 레코드와 시퀀스 번호가 일치할 때 병합합니다.
- 하드 링크는 기존 폴더 열거 방식과 같이 **각 경로에 크기를 집계**합니다. DOS 8.3 별칭은 중복 집계하지 않습니다. ADS는 집계하지 않습니다.
- NTFS 시스템 메타파일(예약 MFT 번호 0~15)과 `$Extend` 아래 항목은 제외합니다. 재분석 지점도 추적하지 않습니다.
- 일반 파일의 드문 **nonresident ATTRIBUTE_LIST**는 관찰된 확장 레코드를 병합하되 완전성을 확정하지 않습니다. 확인하지 못한 확장 참조와 함께 해당 폴더를 부분 집계로 표시하고 오래된 폴더 후보에서 제외합니다. MFT 자체의 속성 목록은 최대 16 MiB, 확장 참조는 4,096개까지 읽으며 범위를 넘으면 기존 스캔으로 전환합니다.
- 관리자 MFT 스캔은 일반 폴더 접근 권한으로 볼 수 없는 항목의 메타데이터도 볼 수 있습니다. 메모리는 파일 레코드·파일명 수에 비례해 사용하며 파일이 수백만 개면 수백 MiB 이상 필요할 수 있습니다.
- 라이브 볼륨의 일관된 스냅샷을 보장하지 않으며 Windows 접근 시각의 갱신 제약도 그대로입니다. 관리자 권한의 실제 볼륨 속도·호환성은 환경별 확인이 필요합니다.

구조 참고: [MFT 레코드 헤더](https://learn.microsoft.com/en-us/windows/win32/devnotes/file-record-segment-header), [속성 헤더와 runlist](https://learn.microsoft.com/en-us/windows/win32/devnotes/attribute-record-header), [볼륨 정보](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-ntfs_volume_data_buffer).

## 사용법

- 면적은 폴더 아래 파일의 논리적 크기 합계입니다. 색상은 최근(청록) → 6개월(노랑) → 1년 이상(빨강), 날짜 미확인은 회색입니다.
- 블록을 한 번 클릭하면 선택하고, 두 번 클릭하면 해당 폴더로 이동합니다. **상위**, **루트**로 돌아갈 수 있고, 계층 깊이를 1~4로 조절할 수 있습니다.
- 직속 파일은 하나의 블록으로 합칩니다. 각 계층에서 크기순 상위 100개를 그리며 나머지는 기타 폴더로 합칩니다. 하위 폴더 목록에서는 모든 폴더를 탐색할 수 있습니다.
- 오른쪽 목록은 전체 스캔 범위의 오래된 폴더를 크기순으로 최대 200개 표시합니다. 기간, 최소 MiB, 경로 문자열로 필터링합니다. 상위/하위 후보는 중복될 수 있으므로 크기를 합산하지 마세요.
- **경로 복사**, **탐색기로 열기**로 폴더를 직접 확인할 수 있습니다.
- 스캔은 별도 스레드에서 실행됩니다. **중지**하면 읽은 범위의 부분 결과를 표시합니다. 폴더 열거 모드에서는 전체 크기를 미리 알 수 없어 진행률 대신 읽은 폴더/파일 수와 바이트를 표시합니다.
- 전체 스캔 완료를 기다리지 않고 **잠정 지도**를 표시합니다. 첫 미리보기는 약 250ms 이후 파일 용량을 읽은 시점부터, 이후 대략 1초 간격으로 갱신합니다. 큰 트리는 갱신 비용에 맞춰 간격을 늘립니다. 운영체제 I/O가 지연되면 첫 표시도 늦어질 수 있습니다.
- 스캔 중 면적은 현재까지 읽은 용량만 나타내며 크기·색상이 바뀔 수 있습니다. 지도 탐색 위치는 갱신 후에도 유지하고, 오래된 폴더 후보는 스캔 완료 후 확정합니다.
- 기존 폴더 열거 모드는 Windows 열거 결과의 메타데이터를 재사용해 파일별 추가 조회를 제거했습니다. 상위 계층부터 너비 우선으로 순회하여 주요 폴더를 먼저 발견합니다. [Rust DirEntry 문서](https://doc.rust-lang.org/std/fs/struct.DirEntry.html#method.metadata)

## 날짜와 집계 기준

기본 날짜는 폴더 자체 및 하위 모든 폴더/파일의 **가장 최근 수정 시각**입니다. 접근 기준은 **하위 파일의 가장 최근 접근 시각**만 사용합니다. 디렉터리 열람에 따른 영향을 줄이기 위해 폴더의 접근 시간은 사용하지 않습니다. 날짜를 하나라도 읽을 수 없으면 그 기준은 미확인으로 처리합니다. 미래 날짜는 0일 전으로 표시합니다.

수정되지 않은 파일도 자주 읽힐 수 있고, Windows의 접근 시간은 비활성화되거나 갱신이 지연될 수 있으므로 날짜는 실제 사용 빈도의 추정 자료입니다. [Microsoft의 파일 시간 설명](https://learn.microsoft.com/en-us/windows/win32/sysinfo/file-times)을 참고하세요.

- 개별 파일의 내용을 열어 분석하지 않습니다. MFT에는 작은 파일의 resident 데이터도 포함될 수 있지만 크기와 메타데이터만 사용합니다. 폴더 열거에서는 접근 거부/사라진 파일 등을 건너뛰며 오류 수와 최대 100건의 상세를 표시합니다. 일반 권한으로 시작할 수 있습니다.
- 심볼릭 링크, junction 등 모든 Windows 재분석 지점은 순환/다른 드라이브 추적을 피하기 위해 제외합니다. 클라우드 placeholder 등도 이에 해당할 수 있습니다.
- 읽기 오류·제외 항목이 있는 폴더와 그 상위 폴더는 부분 집계로 표시하고 오래된 폴더 후보에서 제외합니다. 중지된 결과도 후보에서 제외합니다.
- 논리적 파일 길이를 더하므로 압축/희소 파일의 실제 할당량, 하드 링크의 중복, 시스템 예약 영역을 반영한 Windows 드라이브 사용량과 다를 수 있습니다.
- 스캔 중 변경되는 파일 시스템의 일관된 스냅샷을 보장하지 않습니다. 기존 폴더 열거 방식은 폴더 정보만 메모리에 유지하고, MFT 방식은 파일 레코드도 유지합니다.
- 네트워크/응답 없는 드라이브의 운영체제 I/O 호출이 지연되면 중지 반영도 지연될 수 있습니다.

## 개발 확인

```powershell
cargo fmt --check
cargo test
cargo clippy --all-targets -- -D warnings
cargo build --release
# 폴더 50,001개의 저장 지도 복원 시간 측정 (임시 테스트 DB)
cargo test --release benchmark_restore_50000_directories -- --ignored --nocapture
# GUI 없이 자동 엔진 선택과 첫 지도 표시 시간 확인
cargo run --release -- --scan-check "C:\"
# 관리자 PowerShell에서만: 실제 볼륨 MFT 테스트 (자동 전환하지 않음)
$env:DISKMAP_MFT_VOLUME = 'C:\'
cargo test --release live_mft_volume_scan -- --ignored --nocapture
```

`scan.rs`: 취소 가능한 순회, 날짜/크기 집계, Windows 드라이브 목록.
`treemap.rs`: 면적 비례 이진 분할 레이아웃.
`app.rs`: 한국어·영어 UI, 탐색, 후보 필터, 색상 지도.
`i18n.rs`: 언어 설정 저장, UI 번역 도구, 저장된 진단 메시지 표시.
`mft.rs`: NTFS 레코드/속성/runlist 파서와 참조 기반 계층 집계.
`mft/windows.rs`: 읽기 전용 볼륨 접근, 정렬된 일괄 읽기, MFT 스캔.
`cache.rs`: SQLite 저장/복원, 트랜잭션, 형식·계층 검증, 백그라운드 DB 작업.
`subtree.rs`: 현재 폴더 재스캔, 삭제 확인, 상위 집계와 기존 지도 병합.
